# CS2Stats 1.3.1 更新说明

发布日期：2026-11-24

## 修复

### 1. 人机居多的对局（cbble）报告只显示 1 个回合

- **根因**：`.dem` 文件本身只录制了约 108 秒的游戏数据——第 1 回合完整
  （freeze end tick 2494 → 回合结束 5275 → 正式结束 5723），第 2 回合
  在 tick 6683 开打后仅约 4 秒录制就终止（文件 6.5 MB，对比同晚 cache
  整场的 72 MB / 13 回合）。这是 GOTV 录制截断，不是解析漏回合，
  也不是非现役地图缺坐标（该 demo 击杀坐标完整）。
- **修复**：解析层新增"截断录制检测"——用游戏状态事件
  （`round_freeze_end`）补充核对 awpy 的回合表。任何已开打
  （freeze time 结束）但没有回合结束记录的回合会被标记为
  `still_in_progress`：
  - **不计入任何统计**（不产生错误数据）；
  - 在报告的警告区与 `data_quality.recording_truncation` 中明确说明
    "demo 录制不完整"，并列出具体回合号与 tick；
  - 若实际对局远不止这些回合，警告会明确告知是 `.dem` 文件本身
    只录了一部分，解析无法还原未被录制的内容（不静默降级）。
- **验证**：cbble demo → 1 个正式回合 + 第 2 回合（tick 6683）截断警告；
  cache（13 回合）、mirage（16 / 14 回合）回归无误报；
  mirage fixture 10 人 × 4 项（K/D/A/ADR）校验全部一致。

### 2. 实时监听：进入地图后立刻报"dem 无法解析"

- **根因**：竞态条件。`exec stats` 后进入地图时 GOTV 立即创建 `.dem`
  并写入头部，随后地图加载期间文件可能数秒不增长；监听器看到"文件稳定"
  就立刻解析，拿到的是不完整文件，于是报错。且旧逻辑在解析前就
  标记"已处理"，失败也不会重试。
- **修复**（`cs2stats/demo_watch.py`）：
  - 解析**成功后才**标记"已处理"；失败不再污染状态。
  - 不完整类错误（ParseError 等）**重试而非报错**：指数退避
    （5s/10s/15s…最多 6 次，约 100 秒窗口），期间文件若继续增长
    （录制中）会自动重置计时，等录制结束后正常出报告。
  - 小于 16 KB 的 `.dem` 直接判定为"仍在创建"，不解析、不报错。
  - 重试耗尽才报一次错（文件确实损坏的情况），且**单个文件失败不会
    导致监听进程退出**。
  - fixture 不一致（ValidationFailed）属于硬错误：立即报告、不重试，
    保证数据完整性语义不变。
- **验证**：仿真测试（截断文件 → 持续增长 → 完整文件）全程零错误弹窗，
  最终自动出报告且 fixture 校验通过；永久损坏文件在 3 次重试后报错一次，
  监听进程保持存活。

### 3. 手动选择 Demo 不再强制要求计分板 fixture（v1.3.1 既有改动）

- 没有找到 fixture 时，仍然生成报告，顶部标注"未校验"，并在成功弹窗中提示。
- 找到 fixture 但与 demo 不一致时，仍然停止生成并列出差异。
- 命令行手动模式默认允许缺少 fixture；需要强制校验时加 `--require-fixture`。
- README 与 `fixtures/FIXTURE_FORMAT.txt` 同步说明。
