# CS2Stats 1.4.2 更新说明

发布日期：2026-11-26

## 一句话总结

修复自动监听的竞态问题：demo 文件还没录制完成就被拿去解析导致报错。
就绪判据升级为多重采样 + 解析失败按错误类型分类兜底，单文件异常不再
影响监听进程，全程有日志可查。只改监听/调度层（`cs2stats/demo_watch.py`），
解析层与数据逻辑零改动。

## 问题根因

旧实现的就绪判据是"文件大小/mtime 连续约 3 秒不变即解析"（1 秒轮询 × 3 秒窗口）。
但 CS2 录制 demo 是分块写入的，中途会有数秒的停笔间隙——3 秒窗口会在
两次写块的间隙里误判"录制完成"，对仍在写入的文件发起解析，报
"dem 无法解析"一类错误。

## 修复内容

### 1. 就绪判据升级为多重采样（全部通过才解析）

- **大小下限**：不足 256 KB 的 .dem 直接视为录制中（完整比赛 demo 至少
  数 MB），持续等待，不解析、不报错、不消耗重试次数；长时间不增长
  （≥60 秒）提示一次"疑似中止的录制"。
- **采样计数**：大小和 mtime 需连续 3 次采样保持不变，采样间隔 ≥3 秒
  （即最后一次写入后约 9 秒才判定就绪），单次匹配永不判定就绪。
- **辅助信号**：同目录出现更新的 .dem 时，直接判定前一个文件录制已结束
  （CS2 一个服务器同时只录一个 demo），无需再等采样。

### 2. 解析失败分类兜底

- 依据真实捕获的 demoparser2 错误文本分类：
  - 可重试（判定为"还没录完"）：`outside command stream`（截断文件）、
    `unexpected EOF`、`failed to fill whole buffer`、文件占用
    （Permission）、内容暂不完整（demo.stats 为空）等；
  - 硬错误（真损坏，直接报错不重试）：`magic bytes mismatch`（垃圾文件）、
    `snappy corrupt input`（解压损坏）、其他未知错误。
- 重试走指数退避：5s → 15s → 30s → 30s → 30s，最多 5 次；重试期间
  监听循环照常运行，绝不因单个文件退出。
- 重试耗尽后明确报错并写入日志（含日志文件路径），不静默丢弃。

### 3. 日志细化

每个被监控文件的采样值（大小 MB）、连续稳定计数、就绪判定、辅助信号、
重试次数与退避时长、错误分类结果全部写入
`%LOCALAPPDATA%\CS2StatsReport\logs\app.log`，事后可完整还原判定过程。

## 验证

- 单元测试 13 个新增（共 28 个全绿）：错误分类、3 次采样门槛、
  大小变化重置、退避序列、重试耗尽报错、硬错误不重试。
- 模拟验收 1（截断文件）：1 MB 截断 demo 放入监听目录 → 采样就绪后解析
  失败被正确分类为"还在录"→ 5s/15s/30s 退避重试，全程无报错无崩溃；
  中途删除文件，监听继续运行。
- 模拟验收 2（辅助信号）：重试退避期间放入更新的 demo → 旧文件被
  立即判定录制结束并重试，不受退避剩余时间阻塞。
- 模拟验收 3（完整流程）：71 MB 完整 demo 按 8 MB 分块、每块停 4 秒
  写入（旧判据必误判的场景）→ 写入期间零解析尝试；写入结束后约 9 秒
  自动解析，fixture 校验 40 项全过，报告正常生成。
- 回归：compileall、28 个 unittest、mirage fixture 精确层校验全部通过。

## 兼容性

- `DemoWatcher` 构造函数新增参数均有默认值，GUI / CLI 现有调用不受影响；
  `--watch-stable` 参数保留（作为总稳定窗口下限，采样计数为主判据）。
- 已录完的历史 demo 走完全相同的路径，不受影响。
